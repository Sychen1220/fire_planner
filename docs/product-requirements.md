# 半 FIRE Planner 产品需求文档

> 版本：V0.7｜状态：页面层级已修订，M1-05 待实现与验收，其余阶段按计划实施｜更新日期：2026-10-06
> 实施依据：本稿、[技术设计 V1.4](technical-design.md)、[M1 执行规格](implementation-spec.md)。[V0.6 原型快照](prototypes/fire-planner-v0.6.html)保留作历史交互参考，导航归属以本稿为准。软件包仍为 0.1.0，文档更新不代表功能上线。

V0.7 修正此前“四页全部嵌入 FIRE 计划”的结构：取消独立首页入口，将其有效摘要和引导归入已有工作区域；FIRE 计划仅含我的生活、我的资产、开始测算三个工作页。保留预算、资产、测算能力不等于保留旧导航壳。此前 128 项测试通过未覆盖新层级，不能据此认定 A01 已完整通过；M1-05 须修正后重新验收。本次仅修改文档。

## 1. 项目目标

**在同一个产品里，用实际执行持续校正半 FIRE 预测，并帮助用户判断一笔消费带来的生活价值，是否值得承担相应的计划代价。**

目标用户正在积累资产或准备降低工作强度，希望减少盲目花钱、保留生活品质，培养长期主义的消费习惯。节省金额和购买率不能单独衡量产品成功；用户应能说清这笔消费得到什么、付出什么、哪些条件仍不确定。

已确认原则：

- 在现有 FIRE Planner 上叠加功能，保留生活、资产、测算的表单、图表和计算能力；导航按用户任务重新归属。
- 一个产品、同一份财务上下文，三个模块可以独立进入。
- 实际收支改变最新 FIRE 预测；保留原定目标是为了比较，不代表预测不变。
- 消费判断以最新预测为起点，通过自然语言对话完成，不要求填写购买问卷。
- 退出时间允许权衡。AI 说明生活价值和计划代价，由用户决定是否接受。
- 审美、愉悦、纪念意义都是正当价值；不急着买不等于不值得买。
- 财务数字由程序计算，AI 理解需求、追问和解释，不编造余额或退出日期。

## 2. 原型对齐与范围变化

此前确认的 V0.6 原型为 `fire-planner-monthly-history.html`，仓库内保存为[原型快照](prototypes/fire-planner-v0.6.html)。快照含演示数据和交互，不连接正式数据库或 AI。下表保留 V0.5 → V0.6 的范围演进；V0.7 对首页和导航的修订见第 3 节，并覆盖此前“保留四页入口”的约束。无需新增全局首页或把首页改名为另一个概览页。

| V0.5 旧方案 | V0.6 已确认方案 |
|---|---|
| 首页增加入口，在旧表单里插入预实功能 | 顶层并列 FIRE 计划、实际收支、消费判断，原 Planner 收入 FIRE 计划模块 |
| 消费表单、结果卡、固定选择按钮与回看子流程 | 输入框与对话区；追问、生活价值和计划影响在对话中展开 |
| 当前期间摘要、切换单月、单月预实详情 | 月度历史汇总表；删除独立单月详情区，点击月份直接编辑 |
| “实际更新不改计划”容易被理解为没有联动 | 原定目标保留，最新预测随实际更新，消费判断读取同一预测 |
| 决定管理、结果记录与价值回看各列为 P0 | 首版保留对话与明确表达的事实；不建设独立决定、复盘页面或强制流程 |

最后一项是实现范围收敛：用户仍可在对话中表达买了、没买和使用感受，系统不能自动转为收支入账；结构化复盘、提醒和经验统计后置。

### 2.1 原型与正式能力的区别

- 原型用“原节点资产 + 可比完整月结余差额”展示联动。正式版必须按月重跑，不能照搬节点加减作为预测算法。
- 原型 2026 年 7–10 月收支及每月 50,000 元收入、10,000 元支出均为示例，不导入用户账目。
- A/B/E 是对话案例，B 是本次倾向；正式版由用户明确选择参考方案，不硬编码 B。
- 原型尚未接入真实 AI，也未计算退出日期。正式版提供真实对话；退出条件明确时计算可核对的月份，资料不足则保持未知。

## 3. 页面结构与首版范围

顶层按三项用户任务组织：FIRE 计划用于规划未来，实际收支用于记录已发生的事实，消费判断用于讨论是否值得花这笔钱。三者并列。FIRE 计划内部再按生活预算、资产条件、方案测算划分工作页。

```text
FIRE 计划
├─ 我的生活
├─ 我的资产
└─ 开始测算
实际收支
消费判断
```

产品不设独立“首页”入口，FIRE 计划内也不另设“计划首页／概览”子页。原首页的预算、资产摘要与进入测算按钮重复了现有工作页的内容，不承担独立任务。

模块导航与子页面导航必须有清楚的层级区分。可以沿用侧栏展示，但只有选中 FIRE 计划时，才显示三个工作页入口及计划管理操作；切到实际收支或消费判断后，这些入口与操作隐藏，而不是仅禁用。摘要、表单按钮和历史计划选择都是页内内容，不再提升为导航层级。

| 当前模块 | 子页面与操作 | 参照展示 |
|---|---|---|
| FIRE 计划 | 我的生活、我的资产、开始测算三个工作页；参考方案选择、确认／保存计划、取消草稿、历史计划选择及设为参照 | 正式计划摘要与草稿差异；最新预测按阶段接入 |
| 实际收支 | 自己的月度记录操作；M1 仅显示待开发 | 可复用只读正式参照／预测摘要，不展示计划编辑控件 |
| 消费判断 | 自己的对话操作；M1 仅显示待开发 | 可复用只读正式参照／预测摘要，不展示计划编辑控件 |

切换模块后，主内容区仅展示当前模块。返回 FIRE 计划时恢复上次子页面及当前会话草稿；模块切换不确认、不取消草稿，也不改变正式参照。没有完整计划也可以进入其他模块，M1 的待开发提示不要求先保存计划。

新会话默认进入 FIRE 计划 → 开始测算，直接展示方案工作区；资料缺失时在该页提示前往“我的生活／我的资产”补充，不先经过欢迎首页。已有正式计划时恢复其参数并展示正式参照；没有正式计划时清楚标记草稿，不能把预填默认值当成已确认资料。同会话返回模块优先恢复上次工作页。

### 3.1 FIRE 计划

保留我的生活、我的资产、开始测算三个工作页。其主体布局、录入方式、多方案比较、逐月曲线、公式与原有计算语义不重设计。旧首页不再作为页面渲染。

在 FIRE 计划模块内部、三个工作页主体之外提供最小参照区域：保存完整测算、选择参考方案、显示原目标与最新预测。这里的“外层”仍归属 FIRE 计划，不能解释为所有模块都展示计划管理控件。其他模块可以共享只读摘要。原型的“现有 Planner 保留区域”只是历史边界说明，开发时连接真实工作页，并按本稿移除首页入口。

旧首页内容按用途处理：

| 原首页内容 | 新位置与处理 |
|---|---|
| 年度预算、可提款金融资产 | 复用生活、资产和测算页已有指标，不再复制成独立首页；草稿指标与正式摘要分别标明来源 |
| 完全 FIRE 参考值 | 沿用测算中的参考展示与同一提款率参数，保留公式，不复制旧首页固定 3.5% 的独立口径 |
| 资料准备提示、开始测算入口 | 在测算页按缺失资料提示跳转到生活或资产；已处于测算页，不再显示“进入测算”的重复按钮 |
| 产品欢迎文案、固定完成进度 | 不再单独占一页；不把系统默认预算或正资产金额直接视为用户已确认完成 |

- 保存预算、金融资产范围、收入、一次性事件、收益假设、提款率、退出月份及预测范围。
- 原页面编辑仍可试算；保存为正式参照时明确确认，不把每次控件变化自动当作新目标。
- 实际更新后展示最新预测，保留已确认目标与当时结果作对照。
- 资产总额与可付款现金分别表达，不自动将房产计入可提款资产。

### 3.2 实际收支

默认展示月份倒序的历史汇总表：

| 列 | 展示要求 |
|---|---|
| 月份 | YYYY-MM；未完成月份注明累计截至日 |
| 收入 | 已确认的当月累计收入；未知不显示为 0 |
| 支出 | 当月累计净支出；必要退款说明可保留 |
| 结余 | 收入减支出；任一未知则显示“待补充” |
| 结余较计划 | 仅比较同期、同范围、可比计划；否则显示“—”并解释 |

提供“记录 / 补录月份”。点击历史月份直接编辑，保存后返回汇总表，**不再展示独立的“单月收入／支出／结余预实详情”**。

表单含累计截至日、当月收入、当月净支出、可选的同日日终金融资产。日期确定所属月份，一月只有一份有效累计总额；修正替换旧值并保留修订，不把历次累计相加。允许补录历史，缺失月份不伪造为零。修改时预填旧值；清空字段表示明确改为未知。

表下方仅增加简短 FIRE 影响摘要：原目标节点、最新预计资产、退出时间变化或无法计算的原因。假设按需展开，不恢复单月详情面板。

### 3.3 消费判断

默认只有当前参照摘要、对话区、输入框和发送操作。

- 直接输入“我想买……”，没有固定购买表单、价值评分、多方案卡片或必选决定按钮。
- 摘要引用所选方案的最新预测，注明有效数据日期和缺口。
- 每轮通常补问 1～2 个最影响判断的问题，复用用户已说过的事实；不是固定问卷或轮数限制。
- 生活价值、建议、财务影响和必要条件直接写在回复中；长公式按需展开。
- 切换模块保留对话和草稿；已发送消息持久化，刷新或重启后可继续。
- 支持开始新对话和从轻量历史列表恢复旧对话，不另建消费管理中心。
- 可表达选择、实际购买和感受，只保存明确内容。“可以了”“谢谢”不等于同意购买。

无计划也可先聊价值。AI 未配置或调用失败时保留输入、说明失败并允许重试，不把固定话术冒充模型回答。原型的“查看 Niki 示例”是演示入口，不是正式主流程要求。

### 3.4 P0 与后置范围

| 编号 | 首版 P0 | 完成边界 |
|---|---|---|
| P0-1 | 原 Planner 与参考方案 | FIRE 计划仅含生活、资产、测算三个工作页，无独立首页；计划管理限本模块，切换返回不丢草稿；原计算回归正常，完整方案和选择可恢复 |
| P0-2 | 月度实际收支 | 历史汇总、补录、修改、未知值、可比预实 |
| P0-3 | 实际驱动预测 | 收支变化刷新共享预测；目标可对照；历史不重复计算 |
| P0-4 | 对话式消费判断 | 自由输入、按需追问、程序计算、AI 解释、引用最新预测 |
| P0-5 | 数据与对话可靠性 | 本地持久化、幂等、版本一致、错误恢复和依据追溯 |

后置：独立决定管理、结构化复盘、30/90 天提醒、经验统计、生活情景中心、独立未来支出管理页、逐笔流水和分类账、银行连接、退款自动对账、后台通知、多用户及移动端专用应用。

不做自动下单、投资交易推荐、消费人格评分、固定冷静期或固定比例购物额度，不要求消费前完整记账。

## 4. 共享数据与联动

| 信息 | 作用 | 改变方式 |
|---|---|---|
| 原定计划 | 已确认目标、假设与安排，作为比较基准 | 明确保存新计划时新增修订 |
| 已确认实际 | 月度收支、带日期资产观测 | 用户保存或纠正事实 |
| 最新预测 | 原计划结合实际及剩余假设的推演 | 财务依据变化后失效并重算 |
| 消费模拟 | 在同一最新预测上增加或替换候选支出 | 分析计算，不修改账目或目标 |
| 对话历史 | 用户意图、建议及当时依据 | 追加消息；旧回复保留当时版本 |

**保存实际 → 实际版本更新 → 旧预测失效 → 重算最新预测 → FIRE 摘要和下一轮消费判断读取同一结果。**

重算失败不撤销已经保存的账目，须显示“实际已保存，预测更新失败／待补充”。旧结果注明旧依据，跨页面也不能重新当作最新结论。

例如原定 2027-08 退出，最新预计需要更久，应呈现两者差异，由用户决定是否调整目标。只有退出条件、积累路径和预测范围明确时才能计算延后月份，不能用支出除以月储蓄直接生成日期。

## 5. 实际收支如何影响预测

### 5.1 统计口径

收入包括工资、奖金、兼职等外部现金收入，不将内部转账、卖出资产本金或已计入投资回报的收益重复计入。支出为生活消费与对外付款净额，投资申购、内部转账不算消费。房贷月供已含预算时不再重复计算；房贷余额不从 FIRE 金融资产再扣一次。

计划区分当前工作阶段与退出后阶段。年度预算月均值可作预测假设，但不是实际发生排期；未经确认不能据此断言某月超支或有剩余购物额度。

### 5.2 更新规则

- 完整月份以实际替换同口径计划现金流，不是在原预测上再加一遍实际。
- 单侧收入或支出未知时可沿用该侧计划作条件估计，明确标注，不能称为已核实余额。
- 单月超支不自动延伸成未来每月超支；未来默认沿用已确认计划。
- 月中累计不能代替整月现金流。缺少剩余期间安排时先保存，预测标为待补充或条件估计。
- 有同范围日终资产观测时从其后推演；已经包含的历史收支、购买和收益不重放。
- 月末观测从下月开始；月中观测仅计算余下期间。投资变化和消费差异分开，未知差额不归咎于消费。
- 补录早于当前资产观测的月份可改变历史预实，不再改变已包含这些收支的资产起点。

### 5.3 防止重复入账

累计支出从 8,000 改为 10,000 元，有效值就是 10,000 元。“买了一个 2,000 元的东西”已包含其中时，不能再变成 12,000 元。

“决定买”不写入实际。“已经买了”只保存表达的事实；是否包含在月度总额不确定时补问或引导更新。已发生购买不能继续当作未来新增支出；购买事实与账目矛盾时先核对。

## 6. 对话分析策略

### 6.1 生活价值与计划代价

自动复用方案、最新预测、已确认实际、资金边界和本轮事实。只补充影响本次判断的内容：物品、金额、时点、期待的改善、资金来源、可替代安排和持续费用。

| 情况 | AI 行为 |
|---|---|
| 长期喜欢且体验认可 | 承认价值依据，不要求必须高频使用或急需 |
| 价值不明确 | 建议试用、比较或观察，说明要验证什么 |
| 价值明确但减少 FIRE 积累 | 解释交换关系、给出倾向，再讨论可接受代价 |
| 触及已确认底线 | 指出具体缺口，寻找可承受办法，不编造可取消项目 |
| 关键资料不足 | 回答有依据的部分，补问事实，不给无条件购买许可 |

预算内不自动支持，预算外不自动劝退。愿意延后退出不等于已接受本次代价。回复默认简短：倾向与原因、主要计划影响、必要未知项。

### 6.2 同一最新基线比较

“不新增本次消费”和“新增本次消费”使用同一实际截点、计划和收益假设。一次性支出只发生一次，持续费用按明确期限计入。

只有已包含基线、尚未发生且确认可调整的预算才能抵扣。17,000 元购买替换未用 10,000 元安排，增量为 7,000 元；未确认额度不能直接扣。暂缓不自动把原预算转成额外储蓄。

支付能力、资产规模和年度预算承受力分别判断。原计划既有缺口、实际执行偏差、本次购买新增影响分开，不能把全部缺口归给本次消费。

### 6.3 版本与历史

每条财务建议绑定当时方案和实际版本。更新收支后旧回复保留并标记依据变化，继续提问读取最新预测。AI 调用期间发生变化时也不能把旧结果发布为最新结论。

## 7. 场景流程

| 场景 | 流程 | 结果 |
|---|---|---|
| 原有规划 | FIRE 计划 → 原页面试算 → 保存参考方案 | 保留原体验，其他模块复用完整参照 |
| 补录与修改 | 实际收支 → 记录或点击月份 → 保存 | 历史更新、预测刷新、目标可对照 |
| 新消费 | 消费判断 → 输入 → 按需追问与测算 | 理解价值、代价及未知条件 |
| 先记账后聊天 | 更新实际 → 继续对话 | 使用最新预测，不重复扣款 |
| 先聊天后记账 | 表达选择 → 独立更新月度总额 | 选择不自动入账，实际更新刷新预测 |
| 无完整计划 | 直接聊天 | 可讨论价值，财务影响待补充 |

这些场景独立进入，不是强制顺序；聊天不强制以购买决定或复盘结束。

## 8. 数据、隐私与错误状态

- 已确认计划、有效月度收支、资产观测、对话及计算依据本地持久化。
- 同一操作重试不重复生成事实；并发修改提示冲突，不静默覆盖。
- 预算不迁移为实际消费，旧资产不补造观测日期；示例只进入独立演示环境。
- AI 仅接收必要摘要、相关对话与程序结果；启用时说明发送范围，密钥不入库或日志。
- 分开处理账目保存失败、预测失败与 AI 失败；保留输入、允许重试，不伪装成功。
- 无 AI 配置仍可用原规划、实际与确定性预测，但不能宣称完整消费判断已交付。
